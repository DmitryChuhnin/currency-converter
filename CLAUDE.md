# CLAUDE.md

Правила этого репозитория: то, что нельзя вывести из кода. Как устроено приложение,
описано в [docs/architecture.md](docs/architecture.md).

## Репозиторий публичный

Всё, что попадает в коммит, видно всем, и из истории git это уже не убрать.

- Ключи, токены, пароли, `.env` не коммитим. Переменные `VITE_*` Vite вшивает в бандл,
  поэтому секрет в них тоже становится публичным.
- Личные данные (почта, адреса, внутренние хосты, скриншоты с чужими данными) не
  попадают ни в код, ни в `docs/`, ни в сообщения коммитов.
- Рабочие заметки, планы и всё непубличное лежат в `docs-local/` и `CLAUDE.local.md`,
  оба в `.gitignore`.
- Перед коммитом просматриваем `git diff --cached` на секреты и личные данные.

## Ветки и релизы

- `main` — прод. Каждый merge в `main` это релиз, на merge-коммите ставится тег версии.
  На прод уходит то, что в `main`. Напрямую в `main` не коммитим.
- `dev` — вся разработка и подготовка релиза. Напрямую в `dev` не коммитим.
- Фича-ветки отводятся от `dev` и называются по смыслу: `redesign`, `fix-zero-rates`.

Флоу:

1. Ветка от свежего `dev`.
2. PR фича-ветки в `dev`, CI зелёный, ревью, merge.
3. Когда в `dev` собран релиз: CI зелёный, приложение проверено в браузере, `version`
   в `package.json` поднята до новой версии.
4. PR `dev` → `main`, merge.
5. На merge-коммите в `main` ставим тег `vX.Y.Z` и пушим его.
6. На сервере запускаем `scripts/deploy.sh`, он собирает и выкладывает `main`. Как устроено
   и что настроить: [docs/deploy.md](docs/deploy.md).

Пушим, открываем PR, мержим и ставим теги только по явной просьбе.

## Команды

- Пакетный менеджер `npm`, лок-файл `package-lock.json`.
- `npm run dev` — dev-сервер Vite.
- `npm run build` — проверка типов `vue-tsc` и сборка в `dist/`.
- `npm run preview` — раздача собранного `dist/`.
- `npm test` — unit-тесты Vitest (`tests/unit`).
- `npm run test:e2e` — e2e Playwright (`tests/e2e`) на production-сборке: Chromium desktop,
  WebKit iPhone, Chromium Android. Нужны браузеры: `npx playwright install chromium webkit`.
- `npm run check` — `vue-tsc`, unit и e2e подряд. Линтера нет.
- Правка поведения идёт с тестом, включая негативные случаи: ошибка API, битый ответ,
  офлайн, граничный ввод. Работа готова, когда `npm run build` и `npm run check` проходят
  и правка проверена в браузере на desktop и mobile.

## Коммиты

- Полностью на английском, и заголовок, и тело.
- Трекера задач нет, поэтому префикс с разделом: `feat(ui): ...`, `fix(rates): ...`,
  `docs: ...`, `chore: ...`.
- Никаких приписок: ни `Co-Authored-By`, ни «сгенерировано ассистентом».
- Коммитим только законченное: коммит сам по себе собирается.

## Подводные камни

- `index.html` в корне — точка входа Vite, без него `npm run dev` не стартует.
  Его уже удаляли по ошибке вместе со старой версией.
- Приложение живёт на подпути `/converter/` (константа `BASE` в `vite.config.ts`). Манифест
  PWA берёт пути из неё, `baseURL` в `playwright.config.ts` прописан руками, при смене
  подпути их надо менять вместе.
- `dist/` в git не хранится, сборка воспроизводится из исходников.

## Стиль

- Комментарии 1–3 строки, сухо, только то, что нужно для поддержки: факт о внешней
  системе, неочевидное решение, ловушка. Пересказ кода и историю правок не пишем.
- Из кода не ссылаемся на то, чего нет в git (`docs-local/` и личные заметки).
- Форматируем только свои строки. Чужие комментарии заодно с правкой не переписываем,
  кроме случая, когда комментарий врёт.
- Английские термины в русском тексте пишем латиницей (`callback`, `merge`), не
  транслитерацией.

## Документация

В `docs/` лежит документация критических узлов: контракт с внешним API, решения с
неочевидной альтернативой, устройство офлайн-режима. Правка такого узла и правка `docs/`
идут в одном коммите. Устаревший `docs/` считается багом.
