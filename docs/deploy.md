# CI и деплой

Состояние на 2026-09-29.

## CI

`.github/workflows/ci.yml` запускается на каждый PR и на push в `dev` и `main`. Шаги те же,
что локально: `npm ci`, браузеры Playwright (Chromium и WebKit), `npm run build`,
`npm run check`. Версия Node берётся из `.nvmrc`. Если тесты упали, трейсы Playwright лежат
в артефакте `playwright-traces`. CI ничего не деплоит и секретов не использует.

## Деплой

Деплой запускается руками на сервере:

```sh
scripts/deploy.sh /path/to/site
```

Скрипт забирает `origin/main`, делает `npm ci` и `npm run build` и выкладывает `dist/`
в каталог сайта через `rsync`. С `--delay-updates` новые файлы встают на место разом в
конце, поэтому посетитель не получит новый `index.html` раньше его ассетов. Файлы прошлой
сборки удаляются после этого (`--delete-after`). Упавшая сборка останавливает скрипт до
`rsync`, и на сайте остаётся прошлая версия.

Тесты скрипт не гоняет, они проходят в CI до merge в `main`.

Откат: revert в `dev`, релиз в `main`, снова `scripts/deploy.sh`.

## Настройка сервера

Делается один раз. Репозиторий публичный, поэтому серверу не нужны ни ключи, ни токены.

1. Поставить `git`, `rsync` и Node той версии, что в `.nvmrc`.
2. Склонировать репозиторий по https в отдельный каталог, не в каталог сайта. Клон
   служит только для сборки: скрипт затирает в нём правки, чтобы собрать ровно `main`.
3. Веб-сервер отдаёт каталог сайта по пути `/converter/`.
4. `index.html`, `sw.js` и `registerSW.js` отдаются с `Cache-Control: no-cache`, иначе
   браузер будет держать старую сборку. Файлы в `assets/` с хешем в имени можно кешировать
   надолго.
