# Архитектура

Состояние на 2026-09-26, сверено с кодом в ветке `redesign`.

## Состав

| Слой | Файлы | Что делает |
|---|---|---|
| domain | `src/domain/*.ts` | чистые функции без Vue: ввод и форматирование сумм, пересчёт, проверка ответа API, подбор шрифта, поиск, порядок |
| services | `src/services/ratesApi.ts`, `storage.ts`, `workerUpdate.ts` | запрос курсов с таймаутом и типами ошибок; `localStorage` с проверкой на чтении; перезагрузка страницы, когда её забирает worker новой сборки |
| stores | `src/stores/rates.ts`, `converter.ts` | курсы и их статус; выбранные валюты, источник ввода, строки для экрана |
| components | `src/components/*.vue` | `HomeScreen` и `AmountCard` (главный экран), `EditScreen` (список валют), `StatusLine` |
| composables | `src/composables/*.ts` | общий размер шрифта сумм, drag to reorder, экран редактирования в истории браузера |

Экранов два, роутера нет. Экран редактирования кладёт запись в `history`, поэтому
системный жест «назад» закрывает его, а не приложение.

## Валюты

Список берётся из ответа API, это 166 кодов на 2026-09-25. Имя, символ и флаг лежат
в таблице `src/domain/currencies.ts`, собранной из CLDR. Код из ответа, которого нет
в таблице, показывается с именем из `Intl.DisplayNames` или просто кодом.

Выбор и порядок валют хранятся в `localStorage` (`converter.selection.v1`). По умолчанию
USD, RUB, VND, THB, KRW. Сумма между запусками не сохраняется.

## Курсы

Источник `GET https://api.exchangerate-api.com/v4/latest/USD`, открытый endpoint без ключа.
Ответ на 2026-09-25:

```
200 {"provider":…,"base":"USD","date":"2026-09-25","time_last_updated":1790294401,
     "rates":{"USD":1,"AED":3.67,…}}          166 кодов
```

Контрольный запрос `GET …/v4/latest/XXX` на ту же дату:
`404 {"result":"error","error_type":"unsupported_code"}`.

`parseRatesPayload` в `src/domain/rates.ts` принимает ответ, только если `base` равен
`USD` и `rates` это объект. Курс, который не является конечным положительным числом,
выбрасывается поштучно: валюта остаётся на экране с пометкой «No rate», а не с нулём.
Пометку получает только валюта, которой нет в загруженных курсах. Когда курсов нет
совсем, причину объясняет плашка ошибки, а поля остаются пустыми.

Строка статуса показывает два времени: `Rates 8 Oct, 07:00 · checked 14:10`. Первое это
`time_last_updated` провайдера. Провайдер обновляет курсы раз в сутки в 00:00 UTC, так что
это время честно говорит о возрасте курсов. Второе это время последнего удачного запроса.
Без него ручное обновление в течение дня ничего не меняет на экране и выглядит сломанным.
Время проверки из другого дня показывается с датой, чтобы вчерашние 23:50 не читались как
сегодняшние.

## Пересчёт

Источник это поле, в котором пользователь печатал последним. Остальные поля считаются
через USD: `amount / rate[from] * rate[to]`. Если одного из курсов нет, поле пустое
и помечено «No rate».

Отображение (`formatAmount`): 2 знака; от 1e9 без дробной части; меньше 0.01 две
значащие цифры, потому что `0.00` было бы неверным значением. Ввод ограничен 1e12 и
двумя знаками после точки, лишний символ не принимается. Пересчитанная сумма бывает
больше 1e12 (VND, KRW), её можно уменьшать Backspace, но не увеличивать.

Запятая при наборе это десятичный разделитель: на iOS в русской локали цифровая клавиатура
даёт запятую. Второй разделитель в числе, где он уже есть, не принимается: иначе запятая
посреди `1 234.5` превратила бы сумму в `12.34`. Вставка и перетаскивание текста разбирают
чужую группировку: `1,234.56`, `1.234,56`, `$1,234` дают 1234.56, 1234.56 и 1234.
Разбирается только вставленный текст, остальное поле остаётся как было: `1,234` после `5.`
даёт `5.12`. Одиночная точка остаётся десятичной, потому что `1.234` это обычная сумма в KWD,
BHD и OMR. Цифры с полноширинной, арабской и персидской клавиатур приводятся к ASCII.

Пустое поле показывает серую подсказку: эквивалент 1 USD.

## Ошибки и офлайн

`RatesError.kind` различает `offline`, `network`, `timeout` (10 s), `http`, `format`.
Последний удачный ответ хранится в `localStorage` (`converter.rates.v1`) и сразу
используется при старте, так что офлайн конвертер работает на прошлых курсах.

| Есть сохранённые курсы | Что видно при ошибке |
|---|---|
| да | конвертер работает, `StatusLine` жёлтым: `Offline · rates from …` или `Couldn't update · rates from …` |
| нет | плашка с причиной и кнопкой Retry, суммы не считаются |

Курсы старше 48 часов подсвечиваются тем же жёлтым с текстом `Outdated · rates from …`,
не одним цветом. Обновление запускается при старте, при событии `online` и нажатием на
`StatusLine`. Видимая вкладка раз в минуту проверяет, пора ли: прошло 30 минут с прошлого
удачного запроса, или после упавшего запроса истекла пауза. Пауза удваивается с каждой
ошибкой подряд, от минуты до 30 минут (`retryDelay` в `src/domain/time.ts`), так что 429
или сломанный API не получают запрос каждую минуту. Офлайн запрос не уходит, проверка идёт
каждую минуту. Параллельный второй запрос не уходит. Событие `online` может
потеряться, пока PWA спит, поэтому `refresh()` сверяется с `navigator.onLine` сам.

## PWA

`vite-plugin-pwa` в режиме `generateSW`, регистрирует worker скрипт `registerSW.js`.
Precache держит оболочку приложения и латинский набор шрифта Inter. Ответы API worker не
кеширует: иначе запрос «удавался» бы офлайн, и приложение не узнало бы, что курсы старые.
Worker берёт страницу под контроль с первого визита (`clientsClaim`), приложение
открывается офлайн сразу после первой загрузки.

HTML тоже берётся из precache: приложение открывается сразу, и без сети, и на медленной
сети, и когда сервер лежит. Network-first для HTML отброшен: каждый запуск ждал бы сеть,
а на сети, которая не отвечает (captive portal Wi-Fi в отеле, слабый сигнал), висел бы до
таймаута браузера. Новую сборку браузер находит при запуске: её worker ставится, сразу
активируется (`skipWaiting`) и забирает открытую страницу (`clientsClaim`). Страница,
у которой при загрузке уже был worker, на это перезагружается (`src/services/workerUpdate.ts`),
поэтому новая версия видна в тот же запуск, через несколько секунд после старта. Сумма,
набранная до перезагрузки, пропадает. На первом визите перезагрузки нет: worker там
появляется впервые, а не сменяется.

Конвертер делит origin с основным сайтом и другими приложениями, у каждого свой подпуть.
Cache Storage и `localStorage` на origin общие. Поэтому scope worker ровно `/converter/`,
имена кешей начинаются с `converter-` (`cacheId`), ключи `localStorage` с `converter.`.
Workbox удаляет устаревший precache только своего scope: имя precache содержит scope, и
`cleanupOutdatedCaches` проверяет его. Так же удаляется precache со старым именем
`workbox-precache-v2-…/converter/`, который был до `cacheId`.

До 2026-10-10 `src/main.ts` при каждом старте удалял кеш `api-cache`, считая его остатком
worker до редизайна. Удаление убрано: правило того worker ловило только `/api/` основного
сайта, а конвертер ходил к API курсов на другом хосте. Кеш с таким именем мог завести
только сосед по origin.

Иконки собраны из двух SVG в `public/`. `favicon.svg` со скруглёнными углами даёт обычные
`icon-192.png` и `icon-512.png` с прозрачными углами: их показывают как есть (desktop,
Windows). `icon.svg` без скругления даёт `icon-maskable-512.png` и `apple-touch-icon.png`:
Android и iOS сами обрезают их под свою форму, скруглённая иконка обрезалась бы дважды.
PNG пересобираются из SVG командой `npm run icons`.

## Тесты

`npm run check` запускает `vue-tsc`, unit-тесты Vitest (`tests/unit`) и e2e Playwright
(`tests/e2e`) на production-сборке в Chromium desktop, WebKit iPhone и Chromium Android.
E2E подменяют API через `page.route`, проверяют ошибки (500, обрыв, таймаут, битый JSON,
курс строкой, пропавшая валюта), офлайн, перезагрузку офлайн с service worker.
